# Security & Privacy Policy: Verdict Extension

Verdict is security-critical software designed to protect end-users from online threats while maintaining strict privacy standards.

---

## 1. Core Threat Model

The Verdict Extension protects users from:
- **Phishing attacks** (credential harvesting and brand impersonation).
- **Fraudulent and fake storefronts** (counterfeit goods and unauthorized payment traps).
- **Deceptive payment flows** (unverified or hijacked checkout interfaces).
- **Malicious domain redirects** (drive-by lures and scam navigation chains).

---

## 2. Manifest V3 Permissions Justification

To maintain the principle of **Least Privilege**, the Verdict extension requests only essential permissions:

| Permission / Host | Purpose | Privacy & Security Controls |
| :--- | :--- | :--- |
| `storage` | Persists user toggle (`protectionEnabled`), anonymous device UUID, and transient decision cache. | Data is stored locally in Chrome's sandboxed storage (`chrome.storage.local`). Never uploaded directly. |
| `tabs` / `activeTab` | Observes navigation lifecycle to identify target website URLs and dispatches safety decisions to the active tab. | Tab URLs are normalized and stripped of all sensitive query tokens before analysis. |
| `http://*/*`<br>`https://*/*` | Enables autonomous protection across arbitrary websites on the internet. | **Necessary Rationale**: Scams and phishing campaigns operate across dynamically registered top-level domains. Scoping to an allowlist would eliminate protection on unknown malicious sites. All content script interactions are strictly read-only for metadata extraction. |

---

## 3. Data Minimization & Privacy Guarantees

Privacy is a non-negotiable architectural invariant of Verdict.

### What Verdict NEVER Collects or Transmits
1. **Zero Input Values**: The extension NEVER inspects or reads `.value` on any `<input>`, `<textarea>`, or `<select>` element.
2. **Zero Credentials**: Passwords, PINs, and authentication keys are barred by both key-name blocklists and client-side sanitizers.
3. **Zero Payment Card Data**: Credit card numbers, CVVs, expiration dates, and PANs are blocked by regex pattern scrubbers.
4. **Zero Full DOM / HTML Dumps**: Verdict transmits only structured, high-level structural metadata (e.g. form count, input types, gateway iframe origins).
5. **Zero Cookie / Token Access**: The extension does not read browser cookies, session tokens, or Authorization headers.
6. **Query Parameter Scrubbing**: Authentication tokens, session IDs, and tracking identifiers (`utm_*`, `fbclid`, `token`, `auth`, `key`) are stripped from URLs prior to transmission.

---

## 4. Client-Side Sanitization Verification

All outbound telemetry generated by content collectors passes through `sanitizeSignals()` in `src/collectors/normalization.ts` and `redactObject()` in `src/security/redaction.ts`.

This guarantee is tested and verified continuously in our automated CI suite (`tests/unit/redaction.test.ts`).

---

## 5. Reporting a Security Vulnerability

If you discover a security or privacy vulnerability in Verdict:
1. Please report it privately via email to **security@verdict.example.com**.
2. Do not open public GitHub issues for undisclosed security vulnerabilities.
3. We acknowledge reports within 48 hours and provide remediation updates.
